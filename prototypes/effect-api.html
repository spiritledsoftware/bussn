Does this Effect interface carry the whole Broker contract?

Drive publication, scoped consumption, Claim renewal, release, acknowledgement, Relay loss, and Subscription recreation. The prototype tests whether five explicit Broker operations and one Delivery capability are enough without leaking Store or Relay mechanics to callers.

Recommended seam

Broker — application-facing Module

Five explicit operations. It validates, copies, polls, and hides local-versus-remote wiring.

Store — durable authority Adapter

Owns Message and Delivery commits, Store time, Claim fencing, limits, retention, and status.

Relay — transient transport Adapter

Carries request/response traffic and best-effort wake-ups. It cannot affect correctness.

Effect interface sketch

export interface Broker {
  publish(input: Publication):
    Effect<Message, PublishError>

  createSubscription(input: CreateSubscription):
    Effect<Subscription, SubscriptionError>

  deleteSubscription(id: SubscriptionId):
    Effect<void, DeleteSubscriptionError>

  openConsumer(options: ConsumerOptions):
    Effect<Consumer, OpenConsumerError, Scope>

  subscriptionStatus(id: SubscriptionId):
    Effect<SubscriptionStatus, StatusError>
}

export interface Consumer {
  readonly deliveries:
    Stream<ClaimedDelivery, ConsumeError>
}

export interface ClaimedDelivery {
  readonly deliveryId: DeliveryId
  readonly message: Message
  readonly attempt: number
  readonly claimExpiresAt: DateTime.Utc

  readonly renew:
    Effect<DateTime.Utc, ClaimError>

  readonly release: (options?: {
    readonly delay?: Duration
  }) => Effect<void, ClaimError>

  readonly acknowledge:
    Effect<void, ClaimError>
}

Why this hybrid

Two-method handles

Very small, but lifecycle and status become hidden behind overloaded capability objects.

Automatic consume

Convenient, but forces acknowledgement and handler-failure policy into the Broker.

Explicit ports

Best adapter separation. Retained internally for Store and Relay rather than exposed to callers.

Primitive stream

Lets event, command, job, and plugin libraries add policy without changing Broker core.
